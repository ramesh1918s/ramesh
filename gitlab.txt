```text
                         GitLab.com
                             |

                             | HTTPS
```

```text

    ↓
```

# 6. Create Vault configuration

Create:

```bash
nano /opt/vault/config/vault.hcl
```

Put:

```hcl
ui = true

storage "file" {
  path = "/vault/data"
}

listener "tcp" {
  address     = "0.0.0.0:8200"
  tls_disable = true
}

api_addr = "http://YOUR_EC2_PUBLIC_IP:8200"

disable_mlock = true
```

Replace:

```text
YOUR_EC2_PUBLIC_IP
```

with your actual EC2 public IP.

Save:

```text
CTRL + O
ENTER
CTRL + X
```

# 16. Create restricted Vault token

For your initial GitLab setup, create a token with only this policy:

```bash

  -policy=gitlab-aws-storage \
  -ttl=24h
```

Output:

```text

```

**This token only has read access to `secret/aws-storage`.**

This is much better than giving GitLab the root token.

# 21. GitLab `.gitlab-ci.yml`

Now create:

```text
.gitlab-ci.yml
```

Use this **clean working pipeline** first:

```yaml
stages:
  - validate
  - vault
  - aws

variables:
  VAULT_ADDR: "http://51.21.218.150:8200"
  VAULT_SECRET_PATH: "secret/aws-storage"
  VAULT_VERSION: "1.20.4"

validate_vault:
  stage: validate
  image: ubuntu:24.04

  before_script:
    - apt-get update -qq
    - apt-get install -y -qq curl unzip

    - curl -fsSL "https://releases.hashicorp.com/vault/${VAULT_VERSION}/vault_${VAULT_VERSION}_linux_amd64.zip" -o /tmp/vault.zip

    - unzip -oq /tmp/vault.zip -d /tmp/vault

    - install /tmp/vault/vault /usr/local/bin/vault

  script:
    - echo "Checking Vault..."
    - vault status

  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'


fetch_vault:
  stage: vault
  image: ubuntu:24.04

  before_script:
    - apt-get update -qq
    - apt-get install -y -qq curl unzip jq

    - curl -fsSL "https://releases.hashicorp.com/vault/${VAULT_VERSION}/vault_${VAULT_VERSION}_linux_amd64.zip" -o /tmp/vault.zip

    - unzip -oq /tmp/vault.zip -d /tmp/vault

    - install /tmp/vault/vault /usr/local/bin/vault

  script:
    - echo "Authenticating with Vault..."

    - vault token lookup >/dev/null

    - echo "Reading AWS secret from Vault..."

    - vault kv get -format=json "$VAULT_SECRET_PATH" > vault-secret.json

    - jq -e '.data.data.aws_access_key_id' vault-secret.json >/dev/null

    - jq -e '.data.data.aws_secret_access_key' vault-secret.json >/dev/null

    - jq -e '.data.data.region' vault-secret.json >/dev/null

    - echo "Vault secret retrieved successfully."

  artifacts:
    paths:
      - vault-secret.json
    expire_in: 10 minutes

  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'


aws_test:
  stage: aws
  image: ubuntu:24.04

  needs:
    - job: fetch_vault
      artifacts: true

  before_script:
    - apt-get update -qq
    - apt-get install -y -qq jq awscli

  script:
    - echo "Loading AWS credentials from Vault..."

    - export AWS_ACCESS_KEY_ID="$(jq -r '.data.data.aws_access_key_id' vault-secret.json)"

    - export AWS_SECRET_ACCESS_KEY="$(jq -r '.data.data.aws_secret_access_key' vault-secret.json)"

    - export AWS_DEFAULT_REGION="$(jq -r '.data.data.region' vault-secret.json)"

    - test -n "$AWS_ACCESS_KEY_ID"

    - test -n "$AWS_SECRET_ACCESS_KEY"

    - test -n "$AWS_DEFAULT_REGION"

    - echo "AWS credentials loaded successfully."

    - echo "Testing AWS authentication..."

    - aws sts get-caller-identity

    - echo "AWS authentication successful."

  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
```

# 25. Production upgrade — very important

Current setup:

```text
GitLab
   ↓
VAULT_TOKEN
   ↓
Vault
   ↓
Long-lived AWS Access Key
```

This is **not the final production architecture**.

Recommended:

```text
                  GitLab
                     |
                  OIDC JWT
                     |
                     v
                  Vault
                     |
              Vault JWT Auth
                     |
              Limited Policy
                     |
                     v
             AWS credentials
                     |
                     v
                   AWS
```

Even better:

```text
GitLab OIDC
     ↓
AWS IAM Role
     ↓
Temporary AWS credentials
     ↓
AWS
```

Then you can eliminate long-lived:

```text
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
```

completely.
